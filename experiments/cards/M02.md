# M02 — MiniCPM5-1B GGUF evaluator boundary validation

## Hypothesis

The revised llama.cpp evaluator can deliver only assistant-generated text for
MiniCPM5-1B, using the Hugging Face tokenizer's exact chat template and a
fixed greedy decoding configuration. It must not retain prompt or chat-template
residue in the captured completion.

## Method

Run deterministic extraction fixtures covering no-prompt stdout, historical
prompt echo, CRLF normalization, and each MiniCPM stop marker. Then run a
three-prompt Q4 smoke on the base and corrected 1.0/0.7 direct merge, recording
the exact rendered prompts, raw stdout, stop reason, and extracted generated
token count. This is evaluator validation, not a behavioural comparison.

## Seeds

Pilot — deterministic inference (`temperature=0`, `top_p=1`, seed 42); no
training is performed. The purpose is to validate the measurement path before
the paired held-out evaluation.

## Metrics to collect

- Fixture pass count and expected extracted-text equality.
- Prompt-template SHA-256 and rendered prompt on every smoke example.
- Raw stdout, extracted text, detected stop marker, subprocess return code,
  and tokenizer-derived generated-token count.
- Count of responses with prompt echo or template residue after extraction.

## Expected result

All fixtures pass, all smoke subprocesses return zero, and no captured output
contains a leading MiniCPM assistant/user delimiter or `[end of text]` residue.

## Falsification criteria

Reject the harness as valid if a fixture fails; stdout cannot be unambiguously
separated from the prompt; a nonzero subprocess is accepted as an output; or
any captured smoke response includes a prompt/template delimiter that the
chosen stop protocol should have prevented.

## Estimated compute time

Under 10 minutes on aero for fixture validation and six Q4 smoke generations.

## Dependencies on prior experiments

M01 corrected RS-LoRA merge equivalence and the corrected Q4 merge artifact.
