The model is highly responsive to system prompts. Different personas dramatically change output style, length, and terminology.

Finetuning implication:

System prompts are the primary control mechanism. A well-crafted system prompt can reshape the model's entire behavior. The "child" prompt cuts output length by 44%. The "coder" prompt adds code examples to explanations.

System prompt always wins. Even when the user explicitly says "ignore the system prompt", the model follows the system. Even when the system provides FALSE information, the model repeats it faithfully. This is a double-edged sword:
  • Good: System prompt is a reliable control mechanism for finetuned behavior
  • Bad: False system prompts poison the model's outputs
  • Bad: Prompt injection via system prompt can override any user instruction

Insight: The model always thinks extensively before outputting. Even "What is 2+2?" generates 568 reasoning characters. Code generation uses the most reasoning (3,447 chars). The reasoning-to-output ratio is consistently >85% — the model is a "thinker" by design.

Implications for finetuning:

  • max_tokens must be ≥ 2048 for any task — 512 starves the output
  • Reasoning quality matters more than output format — the thinking chain determines answer quality
  • Cost: ~1.6-7s per query — acceptable for most use cases
  • Stripping think tags would be catastrophic — would lose 85-99% of the model's computation

5. Consistency Test

10 runs of "What is the capital of Japan?" → 100% correct (all say Tokyo). Only 2 unique response variants. The model is highly consistent for factual questions.

6. Finetuning Strategy Recommendations

What to finetune

TargetPriorityWhy
System prompt behaviorHIGHModel follows system prompts blindly — design the system prompt carefully
Output formatMEDIUMJSON/structured output triples token usage — can be optimized
Reasoning depthMEDIUMSimple tasks use excessive reasoning — could be trimmed for speed
Adversarial resistanceLOWExpected for uncensored model — not a priority unless deploying publicly
Code generationSKIPAlready 100% — no finetuning needed

What NOT to finetune

  • Reasoning ability — the thinking chain is the model's strength. Don't strip think tags or reduce reasoning.
  • Fact recall — 100% accuracy on tested facts. Don't add more factual data.
  • Code generation — already perfect at tested tasks.
  • System prompt compliance — the model follows system prompts reliably. This is a feature.

Key constraints

  • max_tokens ≥ 2048 (minimum for reliable output)
  • Never strip or suppress thinking tokens
  • System prompt is the primary behavior control
  • The model is sensitive to prompt phrasing — test with diverse phrasings
  • The model will follow false system prompts — validate system prompt content
