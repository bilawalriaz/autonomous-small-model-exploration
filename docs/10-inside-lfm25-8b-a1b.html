1. What Is LFM2.5-8B-A1B?

LFM2.5-8B-A1B is Liquid AI's on-device Mixture-of-Experts model. It combines three architectural innovations that are usually seen separately:

  • Short convolutions — input-aware gated convolutions that replace some attention layers, giving O(1) per-token compute instead of O(n)
  • Grouped-Query Attention (GQA) — 32 query heads sharing 8 KV heads, cutting KV cache by 4×
  • Sparse MoE feed-forward — 32 experts per layer, only 4 active per token (12.5% sparsity)

The result: 8B-class quality at ~1.5B decode cost. Per-token FLOPs track a 1.5B dense model, while the 8.3B total capacity lets experts specialize across reasoning, code, multilingual, and long-tail knowledge.

Key insight: The model activates only 1.5B of its 8.3B parameters per forward pass. Weight storage scales with total parameters, but compute and state caches scale with the active path.

3. Core Data Structures

Embedding

token_embd.weight:       (128000, 1680)  — token embeddings, 1680-dim
token_embd_norm.weight:  (2048,)         — RMSNorm to project to hidden_size

The embedding dimension is 1680, not 2048. The 368-dim gap is bridged by the shortconv in_proj layer at the first block, which expands 1152→6144 and maps from the projection space to the hidden space.

ShortConv Block (conv layers)

shortconv.conv.weight:     (2048, 3)       — depthwise conv, kernel=3
shortconv.in_proj.weight:  (6144, 1152)    — input projection: 1152→6144 (3× expansion)
shortconv.out_proj.weight: (2048, 1152)    — output projection: 1152→2048

The shortconv is the signature LFM2 component. It replaces standard self-attention in 18 of 24 layers:

  • Depthwise conv (k=3): each channel independently convolved with a 3-element kernel — O(n) not O(n²)
  • In-projection: expands from 1152 to 6144 (3× hidden), creating gate/conv/shift branches
  • Gated activation: silu(branch1) × branch2
  • Out-projection: maps back to hidden space

GQA Attention (6 layers)

attn_q.weight:          (2048, 1152)  — Q projection: 32 heads × 64 dim
attn_k.weight:          (512, 1152)   — K projection: 8 heads × 64 dim
attn_v.weight:          (512, 1152)   — V projection: 8 heads × 64 dim
attn_output.weight:     (2048, 1152)  — output projection
attn_q_norm.weight:     (64,)         — QK norm per head (64 = head_dim)
attn_k_norm.weight:     (64,)

32 query heads, 8 KV heads → 4:1 GQA ratio. Each head is 64 dimensions. QK-norm is applied per-head before attention scoring.

MoE Feed-Forward (22 layers)

ffn_gate_inp.weight:    (32, 2048)           — router: [expert_scores] = hidden @ W_gate.T
exp_probs_b.bias:       (32,)                 — router bias (per-expert)
ffn_gate_exps.weight:   (32, 1792, 1152)     — expert gate: 32 experts, each 1152→1792
ffn_up_exps.weight:     (32, 1792, 1152)     — expert up: 32 experts, each 1152→1792
ffn_down_exps.weight:   (32, 2048, 1008|1470)— expert down: varies by layer type
ffn_norm.weight:        (2048,)               — RMSNorm before FFN
Anomaly: The down-projection dimension varies: (32, 2048, 1008) for conv layers vs (32, 2048, 1470) for attention layers. This suggests the MoE output dimension adapts based on the sub-layer type, possibly to match residual stream dimensions after attention vs conv processing.

Dense Feed-Forward (2 layers)

ffn_gate.weight:   (7168, 1152)  — gate projection: 1152→7168
ffn_up.weight:     (7168, 1152)  — up projection: 1152→7168
ffn_down.weight:   (2048, 5880)  — down projection: 5880→2048

4. Data Flow: Token to Output

Here's exactly what happens to a token as it flows through the model:

INPUT: token_ids = [token_id]  (single token during decode)

STEP 1: Embedding
  hidden = token_embd[token_id]           → shape: (1680,)
  hidden = rmsnorm(hidden)                → shape: (2048,)  [norm bridges dim gap]

STEP 2: Layer 0 (Dense Conv)
  // ShortConv block
  conv_out = depthwise_conv(hidden, k=3)  → shape: (2048,)  [local context: ±1 token]
  projected = in_proj @ hidden            → shape: (6144,)  [3× expansion]
  gated = silu(projected[:2048]) * projected[2048:]  → shape: (2048,)
  conv_out = out_proj @ gated             → shape: (2048,)
  hidden = hidden + conv_out              → residual connection

  // Dense FFN (no MoE)
  hidden = rmsnorm(hidden)
  gate = silu(ffn_gate @ hidden)          → shape: (7168,)
  up = ffn_up @ hidden                    → shape: (7168,)
  ffn_out = ffn_down @ (gate * up)        → shape: (2048,)
  hidden = hidden + ffn_out               → residual connection

STEP 3: Layer 1 (Dense Conv)
  // Same as Layer 0 — dense processing, no routing

STEP 4: Layer 2 (MoE + Full Attention)
  // GQA Attention
  hidden = rmsnorm(hidden)
  Q = attn_q @ hidden                     → shape: (2048,) = 32 heads × 64
  K = attn_k @ hidden                     → shape: (512,)  = 8 heads × 64
  V = attn_v @ hidden                     → shape: (512,)
  // Apply RoPE, compute attention, reshape to (2048,)
  attn_out = attn_output @ attention(Q,K,V)
  hidden = hidden + attn_out              → residual

  // MoE FFN — THE KEY STEP
  hidden = rmsnorm(hidden)

  // Router: which 4 of 32 experts?
  router_logits = ffn_gate_inp @ hidden   → shape: (32,)  [one score per expert]
  router_logits = router_logits + exp_probs_b  → add bias
  router_probs = softmax(router_logits)   → shape: (32,)  [probability per expert]
  top4_indices = topk(router_probs, k=4)  → [expert_a, expert_b, expert_c, expert_d]
  top4_weights = renormalize(router_probs[top4_indices])

  // Expert computation (4 experts only)
  expert_out = 0
  for expert_idx in top4_indices:
      gate_i = silu(ffn_gate_exps[expert_idx] @ hidden)  → (1792,)
      up_i = ffn_up_exps[expert_idx] @ hidden             → (1792,)
      down_i = ffn_down_exps[expert_idx] @ (gate_i * up_i) → (2048,)
      expert_out += top4_weights[expert_idx] * down_i

  hidden = hidden + expert_out            → residual

STEP 5: Layers 3-23
  // Repeat: each layer is either Conv+MoE or Attention+MoE
  // Conv layers: shortconv → MoE FFN
  // Attn layers: GQA attention → MoE FFN

STEP 6: Output
  hidden = rmsnorm(hidden)                → (2048,)
  logits = lm_head @ hidden               → (128000,)  [vocab scores]
  next_token = sample(logits, temp=0.2, top_k=80)

5. The ShortConv Module

The short convolution is what makes LFM2 different from every other transformer. Instead of computing full self-attention (O(n²)), it uses a depthwise convolution with kernel size 3:

Standard Attention:  O(n² · d)  — must attend to ALL previous tokens
ShortConv:           O(n · d)   — only looks at ±1 neighboring tokens

How it works internally

Input: hidden state x ∈ ℝ^(seq_len × 1152)

1. Depthwise Conv: y = conv(x, kernel_size=3, groups=hidden)
   // Each channel independently: y[i] = w[0]*x[i-1] + w[1]*x[i] + w[2]*x[i+1]
   // Only looks at 3 consecutive positions

2. In-Projection: z = W_in @ x   // (6144, 1152) × (1152,) → (6144,)
   // Splits into 3 branches of size 2048:
   //   gate_branch = z[:2048]     — controls what passes through
   //   conv_branch = z[2048:4096] — the convolved features
   //   shift_branch = z[4096:]    — positional shift

3. Gated Activation: out = silu(gate_branch) * conv_branch

4. Out-Projection: result = W_out @ out   // (2048, 1152) × (1152,) → (2048,)

5. Residual: output = x + result
Why this matters: In a 128K context window, full attention requires 128K × 128K attention scores. ShortConv processes each token in O(1) time regardless of sequence length. The model only uses full attention in 6 of 24 layers — the rest are O(1) per token.

6. MoE Routing Mechanics

The router is a simple linear layer that scores each expert for the current token:

Router:
  W_gate ∈ ℝ^(32 × 2048)    — one row per expert
  b ∈ ℝ^(32,)                — expert bias (exp_probs_b)

  logits = hidden @ W_gate.T + b   → (32,) scores
  probs = softmax(logits)           → (32,) probabilities

Top-k Selection:
  // norm_topk_prob = true: normalize AFTER top-k
  top4 = argsort(probs)[-4:]        → indices of 4 highest-scoring experts
  weights = softmax(probs[top4])    → renormalize to sum to 1

Expert Computation:
  // Each expert is a gated FFN:
  output = Σ(weights[i] * expert_i(hidden))  for i in top4
  // Each expert_i:
  //   gate_i = silu(W_gate_i @ hidden)   → (1792,)
  //   up_i = W_up_i @ hidden              → (1792,)
  //   down_i = W_down_i @ (gate_i * up_i) → (2048,)
  //   result_i = down_i

7. Dense vs MoE: The First Two Layers

Why are layers 0-1 dense? This is a deliberate design choice:

Why dense-first matters

The problem with MoE on raw embeddings:

  • Raw token embeddings are high-entropy, under-determined representations
  • The router needs a reasonable hidden state to make expert selection decisions
  • If routing happens on raw embeddings, all experts see noisy input → poor specialization

The solution: Use 2 dense layers to "settle" the representation first. By layer 2, the hidden state has been processed through convolutions (local context) and dense FFNs (non-linear mixing), giving the router a meaningful signal to route on.

This pattern (dense → sparse) is also seen in DeepSeek-V3 and Mixtral-8x22B.

9. Why This Architecture Works

The three-way synergy

ShortConv replaces attention where possible. In a 128K context, full attention is prohibitively expensive. ShortConv gives local context in O(1) per token. The 6 attention layers provide global context at strategic points (every 4th layer).

MoE replaces dense FFN where possible. Instead of one large FFN (7168 intermediate), the model uses 32 small experts (1792 each). The router learns to send different tokens to different experts, enabling specialization without increasing per-token compute.

GQA reduces KV cache. 32 query heads with 8 KV heads means 4× less KV cache than MHA, enabling 128K context on consumer hardware.

10. Anomalies & Open Questions

1. Embedding dim ≠ hidden dim

token_embd is (128000, 1680) but hidden_size is 2048. The 368-dim gap is bridged by the shortconv block's in_proj layer, which operates on a 1152-dim projection space. This is unusual — most models have embedding_dim = hidden_dim.

Possible reason: the 1680-dim embeddings are more memory-efficient (saves 18% vs 2048), and the projection happens in the first conv block which would exist anyway.

2. Variable MoE down-projection dimensions

Conv MoE layers have ffn_down_exps: (32, 2048, 1008) while attention MoE layers have (32, 2048, 1470). The difference: 1470 vs 1008 = 462.

This might relate to the attention output needing a different residual stream dimension, or the down-projection compensating for information lost/gained in the attention vs conv sub-layer.

3. Variable attn_v dimensions

Most attention layers: attn_v: (512, 1152). But layers 10 and 21: attn_v: (512, 1680). The 1680 matches the embedding dimension exactly. This might be an architectural quirk where certain layers operate in the embedding space rather than the projection space.
